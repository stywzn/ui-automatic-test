# 前置知识：无头/有头 & SxS

> UI 自动化跑之前该懂的几个概念。看完对"浏览器怎么被驱动、为什么有头跑不起来"就有底了。

---

## 一、无头(headless) vs 有头(headed)

**一句话**：同一个浏览器的两种运行方式，区别只在**画没画界面**。

| | 有头 headed | 无头 headless |
|---|---|---|
| 界面窗口 | **有**，你能亲眼看到浏览器在点 | **无**，浏览器在后台跑，没有可见窗口 |
| 速度 | 稍慢（要渲染界面） | 快（省了画界面） |
| 适合 | 本地调试、演示、肉眼看流程 | CI/服务器、批量跑、日常回归 |
| 服务器能跑吗 | 不方便（服务器没显示器） | 可以（本来就不需要屏幕） |

**关键点**：无头**不是**"另一个浏览器"，它是同一个 Chromium **不显示窗口**地运行。页面照样加载、JS 照样执行、元素照样能点——只是你看不到。所以**测试结果完全一样**，无头只是"没画面的有头"。

**命令（pytest-playwright）**：
- 默认就是**无头**：`pytest`
- 想看画面加 `--headed`：`pytest --headed`
- 想放慢看清楚：`pytest --headed --slowmo 500`（每步停 500ms）

**没有画面怎么排查失败？**（本机有头暂时用不了，这点尤其重要）
- **截图**：失败时自动截图
- **录像**：Playwright 能把整个测试过程录成视频（我们已装 ffmpeg）
- **Trace（追踪）**：录下每一步的快照 + DOM + 网络，用 trace viewer 像时光机一样回放

> 💡 面试点：被问"CI 里跑 UI 自动化怎么排查失败？"——答"无头跑 + 失败自动存 trace/截图/视频，用 trace viewer 定位"。这比"我盯着浏览器看"专业得多，因为 **CI 服务器上根本没有屏幕可盯**。

## 二、SxS（Side-by-Side，并行程序集）是什么

这是我们**有头模式启动失败**踩到的东西，顺带讲清楚。

### 背景：DLL 地狱
早期 Windows 上，很多程序共用同一个 `xxx.dll`，都丢在 `System32`。A 程序把它升级了，B 程序就可能崩——这叫 **"DLL 地狱"**：一个共享库被改，牵连一片。

### SxS 的解决办法
Windows 引入 **Side-by-Side（并行）机制**：允许**同一个库的多个版本同时存在**，每个程序通过一份叫 **manifest（清单）** 的文件声明"我要用哪个版本的哪个组件"。程序启动时，Windows 读清单、把需要的组件拼成一个 **activation context（激活上下文）**，再启动。

一句话：**SxS = 让不同程序各用各的库版本、互不打架的机制；靠 manifest 声明依赖。**

### 组件分两种
- **共享程序集**：装在系统的 WinSxS 仓库里，多个程序共用（比如 VC++ 运行库）。
- **私有程序集**：只放在某个程序自己的目录里（比如 Chrome 目录里的 `149.0.7827.55.manifest` + `chrome_elf.dll`）。

### 我们为什么踩坑
`chrome.exe` 的清单声明"我依赖一个叫 `149.0.7827.55` 的私有组件"。这个组件的文件**明明都在**它自己目录里、清单也**完好**——但本机的 SxS 机制就是**报"找不到"**（`Activation context generation failed`，错误码 14001）。属于这台机器 SxS 层面的异常，不是文件缺失。

而**无头版**(`chrome-headless-shell.exe`)是**自包含**的、**不走这套 SxS 依赖**，所以照常能跑。这就是"无头行、有头挂"的根源。

### 通俗类比
把 SxS 想成**图书馆的取书单**：`chrome.exe` 交了张单子写"我要 149 号书"，书**就在架上**、单子也没错，但**图书馆的检索系统抽风，说查无此书**。书没丢，是检索系统的毛病。

> 💡 面试点：SxS / manifest / DLL 地狱是 Windows 平台基础。能说清"为什么无头能跑有头不行 → 无头自包含、有头依赖 SxS 私有组件而系统解析失败"，体现你**排查到系统层、不止停在报错信息**。

## 三、本机现状（结论）

| 项 | 状态 |
|----|------|
| 无头模式 | ✅ 可用（pytest 默认），**练习/跑测试不受影响** |
| 有头模式 | ⚠️ 本机 SxS 异常，暂不可用 |
| 看测试过程 | 用**录像(ffmpeg 已装) / trace viewer** 替代，更贴近真实项目做法 |

**所以：直接用无头开工，不用等有头。** 想"看"就用 trace/video。
